Trust — and how to test it yourself

"We can show you the evidence" and "you can check our evidence without trusting us" are different claims, and only the second survives a sceptic. This page shows the gate's own record of itself, names what that record does not cover, and lets you run two commands that make the first claim falsifiable on this machine.

Make the claims falsifiable

Three fixed commands of the POC binary, against the newest demo data root on this machine. No argument, path or command comes from this page — the request chooses which of the three runs and nothing else. If the binary or a data root is missing, the answer is NOT RUN with the reason, not an error wall.

The invariants these commands stand on

invariantwhat would break itwhat catches that here
Zero accepted event loss a row that never reaches a terminal state, or a duplicate side effect after a crash the kill -9 fault-injection drills; the "detection terminal-state guard" control, removed and watched failing
Decisions replay from stored facts a replay that re-inferred anything, or called a provider again pocctl prove — run it above; RC-4, the zero-provider-calls control
A missing observation is never a negative one an absence rendered as "nothing found", a degraded row without its reason RC-1 at parse time and at write time; the degraded-observation refusal, both directions
The ledger is append-only and hash-chained an edited row, a deleted row, a chain check reduced to a length test RC-2 and RC-3; the tamper button above
tenant_id is never read from a request body a query that trusts the body, a write with no tenant context the RLS canary gate — every site-scoped table, write accepted/refused by scope
How to read a green line here. The record is a local run — there is no CI on this account, and the record says so in its own ci field. It names the commit it ran against and whether the worktree was dirty at the time.
