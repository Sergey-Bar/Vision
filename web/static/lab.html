Lab — the exploratory surfaces, named as what they are

These Python tools are where the product idea got tested before it was promised. They are real, runnable, and in places rougher than the Go surfaces — so this page labels every one of them lab demo and keeps them off the gate path. Nothing here is covered by the verification record on /trust, and this page says so before it shows anything.

Live server

tools/live_poc_server.py — the server behind the live console: streams a source, runs detections, serves the fleet view. This repository's /live page talks to the Go live UI; this server is the Python prototype of the same idea.

lab demopy tools/live_poc_server.py

Camera fleet

tools/camera_fleet.py — health, configuration and restart for a set of cameras, with the same honesty rule as the Go side: a camera that is unreachable is reported unreachable, not green.

lab demopy tools/camera_fleet.py

Autonomous operator

tools/autonomous_operator.py — an agent that watches the alert stream, investigates and proposes dispositions, so the operator loop could be felt rather than described. Its decisions are proposals; a human still signs.

lab demopy tools/autonomous_operator.py

Conversational search

tools/conversational_search.py — ask questions over recorded clips in plain language and get grounded answers with the clip they came from, or an explicit “could not see that window”.

lab demopy tools/conversational_search.py

Behavioural learning

tools/behavioral_learning.py — learns from the operator's own acknowledgements which alerts matter at which hours, so the noise figure moves for the reason the operator gave, not for a guess.

lab demopy tools/behavioral_learning.py

YouTube live detector

tools/youtube_live_detector.py — the earliest probe: point it at a public livestream and watch detections appear. It is where the “real camera, not a fixture” requirement was first met — with a companion test.

lab demopy tools/youtube_live_detector.py

What separates this page from the rest of the hub

the Go surfacesthe lab surfaces
Every claim has a red-checked control and a gate that runs it. Tested where the tests exist (test_live_clips.py, test_live_knowledge.py), trusted nowhere they do not.
Red-checked: watched failing when the control was removed. Prototypes: useful, changeable, and named as prototypes on every card.
On the verification record at /trust. Explicitly excluded from that record, and the record says so.
Why show them at all? Because a lab that is hidden is a lab nobody audits. These tools carry the exploration that produced the product decisions — including the ones that were later rejected — and showing them labelled is more honest than showing a repository that pretends it was always this clean.
Nothing on this page is started by this page. The commands are shown so a reader can run them deliberately, on purpose, with their own eyes on the terminal.
